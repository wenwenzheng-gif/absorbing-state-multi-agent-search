# GPT-6-Luna: three tasks, six seeds

Run `.venv/bin/python -u scripts/luna/run.py` from this repository in a detached session. The current execution uses a detached Python session with stdin disconnected, logs at `outputs/gpt-6-luna/supervisor.log`, and PID at `outputs/gpt-6-luna/supervisor.pid`.

The runner copies the documented final `llm_toy.json`, `llm_tcas.json`, and `llm_physics.json` protocols. ODE is the physics `support_v1` task. Every experiment uses literal task seeds 0–5 and `reasoning_effort=medium`. All degrees, 40 agents, task sizes, round counts, budgets, prompts, and stopping criteria remain as defined by those configurations. Three separate smoke tests each use degree zero, two agents, and initial width one; task round counts and environment logic remain unchanged; they are not experimental seeds.

Compatibility configuration selects the existing OpenAI request style and omits unsupported temperature. The local proxy ignores sampling seed and temperature/top_p; independent local RNG states and trajectories remain, but remote sampling cannot be deterministically seeded. The proxy translates Chat Completions to Responses and maps max_completion_tokens to max_output_tokens. No other model is requested.

Three asynchronous task families launch their six independent subprocesses immediately after their own smoke test. Each process retains the existing 12-request internal concurrency. An optional execution gate in the transport observes a supervisor control file, initially permitting all 18 jobs. Two consecutive 30-second windows with at least 12 transport errors reduce the admitted job count 18 → 12 → 9 → 6. A reduced admitted set drains existing in-flight requests and fills vacated slots when jobs finish. A cross-process request gate matches the configured shared proxy MAX_CONCURRENCY (currently 4), preventing client timeouts while queued behind the proxy. The 18 scientific jobs remain independent; this transport limit does not change their scientific workload. No global deadline is imposed. The scientific configurations retain their existing 54,000-second per-process budget.

Each request uses bounded exponential backoff (up to eight transport retries). Each seed has at most three process attempts, using the native episode checkpoint to preserve successful episodes. Failed attempt episode records and summaries are archived; raw request/response and event ledgers are append-only. JSON status records explicitly label final outcomes COMPLETE or FAILED_AFTER_RETRIES. Separate seed directories prevent shared mutable run files. Task aggregation concatenates isolated outputs and invokes the repository's existing summarize and critical_degree modules.

Uploads target only `gpt-6-luna/{synthetic,tcas,ode}` in `TobyYang7/Branching-Search-runs`, with an artifact extension allowlist and no stdout logs, environment files, credentials, or auth files. Missing Hugging Face authentication is recorded without interrupting experiments. Raw outputs are Git-ignored; code and a final compact report belong on the dedicated experiment branch, never main.

The current minimal compatibility smoke criteria require validated branch and experiment decisions plus successful environment advancement into a later round. Synthetic completed its smoke episode; TCAS and ODE satisfied these criteria using preserved partial smoke traces, documented in each `smoke_check.json`. Smoke outputs are excluded from experimental aggregation.

The coordinator can adopt already-running worker PIDs after a restart, avoiding duplicate workers and preserving completed work. `scripts/luna/status.py` prints current status. A separately detached `scripts/luna/finalize.py` waits for combined results, audits secrets, writes compact reports, commits them, pushes the experiment branch, and checks the remote SHA. Its stdout/stderr are in `outputs/gpt-6-luna/finalizer.log`.
